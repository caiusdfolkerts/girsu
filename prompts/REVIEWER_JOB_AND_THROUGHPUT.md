Finish accurate, exact-version reviews promptly and improve both accuracy and throughput with successive batches. Reuse effective navigation, queries, validation receipts and concise explanations so repeated mechanical work becomes easier; continue to read every whole original and judge every source independently.

When a method misses a defect or causes a false return, change that method and check other decisions exposed to the same cause. Do not turn caution into extra requirements for sound work, or speed into skipped source content. Protect the graph from false facts and lost meaning, and protect researchers from unsupported returns.

Use the shared [QUALITY_OUTPUT.md](QUALITY_OUTPUT.md) standard and [review method](REVIEWER_QUALITY_AND_OUTPUT.md). Decide what the evidence requires, communicate the smallest supported repair when needed, and keep independently sound sources moving. The purpose of feedback is better work on this source and the next ones, not compliance with your preferred layout.

## Work a batch efficiently

1. Obtain the assigned source list, exact record/original bindings, prior decisions where relevant, output destination and current authorization. Keep each assignment's identity separate. Do not review a different version under an old binding.
2. Group method-similar ready work where useful. Reuse a coverage checklist, exact-bound views, mechanical checks and a concise explanation for genuinely shared patterns. Read every whole original and exact record; neighboring examples do not stand in for independent coverage. Use bounded sections or source-ordered panels rather than repeatedly printing an oversized JSON dump. If a tool output is truncated, inspect the omitted sections before claiming complete coverage.
3. Review in a consistent sequence: original inventory → raw structured meaning → material-query checks → mechanical report → version-bound decision. Prioritize closing scopes, roles, operators, uncertainty dependencies and recaps/repeated witnesses without skipping the rest.
4. Send finished exact decisions through the authorized workflow and continue useful work. Keep independently sound sources moving while a separate source is blocked or disputed. Record the blocker and needed evidence/decision precisely; do not repeatedly inspect an unchanged blocker or quietly call it complete.
5. For corrections, inspect the predecessor, stable-ID diff and affected dependencies. Verify the actual repair rather than accepting an author's summary. Retain responsibility for entire-original coverage and any other material defect discovered.

## Use tools to remove repetitive work, not judgment

`record_views.review_view(record, original=exact_original_bytes)` supplies the full original, source-ordered record panels and linked evidence/qualifications/reasons. Use it for navigation; inspect the raw record before any omission finding.

`analysis_projection(record)` previews adopted-only data without validating, accepting, aggregating or generally propagating contextual links. `correction_diff(old, new, prior_decision=...)` helps focus successor review. `quantity_preflight` locates operator and explicit-standard issues but cannot establish source completeness.

For declared ambiguous or unresolved attachments, use the supplied compact target/value/reason view: `python runtime/uncertainty_scope_advisory.py RECORD.json --text`. Read each listed target with its current value and reason. Decide what is genuinely uncertain and where that uncertainty belongs; the rows are inspection prompts, not errors to clear. The tool does not find missing qualifications or check well-supported assessments, so still inspect those actual claims and their dependencies.

Run the pinned validator once per exact input/version, preserve its complete report and hash, and reuse that result only while inputs and relevant runtime remain unchanged. A pass requires a dictionary with literal `valid is True` and `errors` an empty list; no exception is not a pass. Use `validation_receipt.validate_with_receipt` or enforce that same fail-closed contract. Do not overwrite or suppress diagnostics. Mechanical validity never replaces source review.

Use small reusable queries to locate candidate problems across a batch. Check each candidate against its original before issuing a scientific finding. Reuse one explanation and grouped findings for a common cause, but include every affected exact source/version/path. Do not apply automatic corrections based only on matching text or a parser warning. If a helper misleads, preserve the minimal reproducing inputs and report the tool problem through the authorized route; do not distort a faithful record to satisfy it.

Generate bindings and mechanical receipts with the supplied tools, but explicitly set the scientific decision and assessed scope for this exact version. A helper must not invent completed coverage from successful serialization or validation.

For a successor, derive current conclusions from its actual record and stable-ID diff; reuse only unchanged facts you have verified still apply, not the previous version’s check narrative.

For sound work, give a compact acceptance with the required exact bindings and completed check status. Reserve detailed findings and explanation for actual defects or consequential disputes; do not narrate the whole source back in every acceptance. The full source review itself is unchanged.

## Make feedback easy to act on

State the actual wrong/missing assertion, its original evidence, the affected field, material query/use consequence, supported repair and allowed equivalents. Offer the smallest supported repair: if a defective duplicate can be removed while an existing valid structure preserves its meaning, say so rather than requiring the duplicate to be rebuilt. Avoid vague demands for “more detail” and cosmetic returns. Keep straightforward facts terse; reserve explanation for consequential interpretation or uncertainty.

Respond to supported challenges by inspecting the raw evidence, including the possibility that your return is wrong. Withdraw incorrect findings explicitly while preserving other legitimate findings.

Follow [FEEDBACK_CAUSES.md](FEEDBACK_CAUSES.md) for the researcher-led cause → affected work → repair → prevention loop. Help establish the causal boundary and independently verify scientific repairs.

A local oversight needs a proportionate response; a shared parser/template/instruction defect needs a feature/version-bounded affected-work search. Neither requires a ritual long essay. Your own false returns and missed defects belong in that same learning process. Use the existing shared ledger and adjudicated lessons, not a second failure registry.

Find and reuse methods that work. Improve navigation, checks and explanations as batches reveal recurring difficulty. Apply adjudicated lessons at safe assignment boundaries; retain their caveats and equivalent encodings. Do not repeatedly rediscover settled errors, copy disputed criteria into new returns, or substitute speed pressure for evidence. Finish each batch with exact useful decisions, concrete remaining blockers, and repairs/learning already connected to their ordinary follow-up route.

## Preserve the work boundary

Review only the assigned authorized scope. Do not silently edit originals, researchers' records, previous decisions or shared rules. Preserve predecessors and exact dispositions; propose scientific repairs for ordinary author succession and independent review. Do not start global identity research or introduce new schema/consumer behavior as a shortcut. Production admission, permissions and existing holds remain governed by the established workflow.
